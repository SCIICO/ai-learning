## 二、核心知识点

### 1. 虚拟环境（venv）的本质

**一句话**：venv 就是一个自带独立 Python 解释器（副本）的文件夹，"激活"只是把它的路径插到 PATH 最前面。

- 创建：`python -m venv .venv` → 在当前目录生成 `.venv/` 文件夹
- 激活的本质：把 `.venv\Scripts` 插到 PATH 前端，之后敲 `python` 优先找到它
- 激活后命令行前面出现 `(.venv)` 前缀 = 提示"你现在用的是谁家的 Python"
- 依赖隔离：每个项目一个 `.venv`，互不污染；`pip list` 可以验证里面只有干净的几个包
- `.venv` 必须进 `.gitignore`（几百 MB 且跨机器不可复用，`requirements.txt` 才是要提交的）

### 2. Git 安装与命令排查

- 安装：`winget install --id Git.Git`（Windows 官方包管理器）
- **排查命令归属**：`where.exe git` 列出 PATH 中所有同名命令，按顺序第一个生效
- 今天踩的坑：环境体检时检测到的 git 2.55.0 其实是 WorkBuddy 自带的便携版（在 `/mingw64/bin/`），系统里根本没装——`where.exe` 是识破这类"李鬼"的工具

### 3. VS Code 终端与环境快照

- VS Code 的**主进程**在启动时对环境变量拍了一张"快照"，之后新开的终端都继承这张旧快照
- 所以**刚装完新软件，新开终端没用，必须完全退出 VS Code 再重开**（不是关窗口，是退出进程）
- 终端下拉菜单（`+` 旁边的 ∨）里可以选 Git Bash / PowerShell

### 4. SSH 密钥认证（挑战-应答）

- 生成：`ssh-keygen -t ed25519 -C "1114259706@qq.com"`
- 两个文件的分工：
  - `~/.ssh/id_ed25519` = **私钥**（绝对不外传，等同于家门钥匙）
  - `~/.ssh/id_ed25519.pub` = **公钥**（随便贴，等同于锁）
- 认证流程：GitHub 用你登记的公钥出一道题（挑战）→ 本地私钥解出答案（应答）→ **密码全程不上网**
- 首次连接会提示 host key 确认（yes）→ 写入 `~/.ssh/known_hosts`，以后不再问
- 指纹核对法：`ssh-keygen -lf ~/.ssh/id_ed25519.pub` 可以在不暴露公钥内容的情况下核对身份

### 5. Git 三区模型（今天最重要的心智模型）

```
工作区 ──git add──> 暂存区 ──git commit──> 本地仓库 ──git push──> 远端(origin)
      <──git checkout--    <----git reset----    <---git pull----
```

- `origin` 只是远端仓库的**别名**（`git remote add origin git@github.com:SCIICO/ai-learning.git` 时起的）
- `git push -u origin main` 的 `-u` = 绑定 upstream 跟踪关系，此后只需 `git push` / `git pull`
- 验证绑定：`git branch -vv`，输出里 main 后面的 `[origin/main]` 就是绑定标志
- push 输出逐行读法：
  - `Enumerating objects: 9` → 本地清点要上传的对象
  - `* [new branch] main -> main` → 远端**新建**了 main 分支（以后再 push 就没有 `new` 字样）
  - `Branch 'main' set up to track 'origin/main'` → `-u` 生效的证据

### 6. 建仓库的一个隐藏坑

在 GitHub 网页建仓库时**不要勾选 "Add a README file"**：勾了会在远端产生一个初始提交，和本地 `git init` 后的历史对不上，push 会被拒（分叉）。本地已经有内容时，远端保持全空最干净。

## 三、今日亲手敲过的命令（速查）

```bash
# 虚拟环境
python -m venv .venv
source .venv/Scripts/activate      # Git Bash 激活
deactivate                          # 退出

# Git 安装与排查
winget install --id Git.Git
where.exe git                       # 查命令到底来自哪

# SSH 密钥
ssh-keygen -t ed25519 -C "1114259706@qq.com"
cat ~/.ssh/id_ed25519.pub | clip    # 复制公钥到剪贴板（避免折行）
ssh-keygen -lf ~/.ssh/id_ed25519.pub  # 核对指纹
ssh -T git@github.com               # 测试 GitHub 连通

# Git 三区全流程
git init
git status
git add .
git commit -m "README: init ai-learning repo"
git remote add origin git@github.com:SCIICO/ai-learning.git
git push -u origin main
git branch -vv                      # 验证 [origin/main] 绑定
git log --oneline
```

## 四、踩坑记录（今天 3 次，全部自己解决）

| # | 现象                             | 原因                                 | 解法                                                                                  |
| - | ------------------------------ | ---------------------------------- | ----------------------------------------------------------------------------------- |
| 1 | VS Code 终端下拉里没有 Git Bash 选项    | git 是刚装的，VS Code 主进程的环境变量还是启动时的旧快照 | **完全退出** VS Code 再重开（新开终端无效）                                                        |
| 2 | 公钥粘到 GitHub 报 "Key is invalid" | 终端里复制公钥时折行带入了换行符（公钥本身没错，68 字符是完整的） | 用 `cat xxx.pub \| clip` 复制，或用 VS Code 打开 .pub 文件全选复制；粘贴时确认贴进的是 **Key** 输入框而不是 Title |
| 3 | 差点勾选 "Add README file"         | 习惯性想初始化仓库                          | 本地已有内容时远端保持空仓库，避免历史分叉导致 push 被拒                                                     |

另一次小插曲：PowerShell 里把 `~/.ssh/id_ed25519.hub` 当命令敲了——**路径不是命令**，路径只是地址，要么作为参数传给命令，要么用 `cat` 打开。（顺带：公钥后缀是 `.pub` 不是 `.hub`）
